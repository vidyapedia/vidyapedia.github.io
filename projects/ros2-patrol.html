01 / Task

Patrol is more than sending goal poses.

A useful patrol robot needs repeatable waypoint sequencing, knowledge of goal outcomes, recovery from navigation problems, and evidence that the route was completed as intended.

02 / Stack

Localization, planning, and control.

AMCL estimates the robot pose against the map. Nav2 plans the route, while the Dynamic Window Approach-based DWB controller scores feasible local trajectories under velocity and obstacle constraints.

LocalizationAMCL
NavigationNav2

03 / Patrol manager

Own the mission state above navigation.

The patrol manager sequences waypoints, waits on action results, records status, and decides whether to continue, retry, or stop. This separates mission logic from the lower-level navigation stack.

Dispatch

Send the next patrol pose through the navigation action interface.

Monitor

Track feedback and terminal result while preserving mission state.

Recover

Handle aborted or failed goals without losing the route definition.

Log

Write comparable run data for later analysis.

04 / Metrics

Turn demos into experiments.

CSV logging captures run-level evidence rather than relying on visual impressions. The analysis focuses on navigation success, traversal behavior, timing, and discrepancies between odometry and the map-relative pose estimate.

Observed systems issueOdometry drift is not merely a plotting artifact; it changes how localization and control performance should be interpreted.

05 / Lessons

Autonomy needs observability.

The project reinforced a pattern that now carries into my other systems: define states clearly, log decisions and measurements, and make recovery behavior part of the design from the beginning.
